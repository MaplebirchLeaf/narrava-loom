# 多语言

`game.default_locale` 指定 Twee 原文语言。翻译只替换有编译期身份的文本，不执行新表达式或控制流。

## 准备语言目录

```text
languages/en/
├── manifest.json
├── translations.nmsg
└── dictionary.json
```

`manifest.json` 声明语言包身份和目标游戏。下面的 ID、版本范围需与自己的游戏对应：

```json
{
  "locale": "en",
  "version": "1.0.0",
  "game": { "id": "tutorial.first-game", "versions": ">=0.1.0, <0.2.0" }
}
```

可选 `fallback` 指向另一已安装 locale。语言包版本属于翻译内容；`game.versions` 匹配游戏版本，
都不跟随引擎版本自动变化。

## 取得模板并填写译文

`I18n.export()` 返回当前编译故事的格式化 JSON 模板，包含 `language`、`dictionary` 和
`passages`。在游戏控制台中读取或由作者工具调用；它返回字符串，不会自动保存文件。

用模板中的稳定 ID 和 source 填写 `translations.nmsg`：

```text
:: p4:Hall:body.2
[source]
你已第 {$visits} 次来到大厅。
[translation]
This is your visit number {$visits} to the hall.
```

这是[示例消息](../../examples/languages/en/translations.nmsg)的真实条目；自己的游戏应复制其
导出模板中的 ID，不要照搬示例 ID。保持 source 与 placeholder 集合不变，可以调整译文中的参数顺序。
普通花括号用 `{{`、`}}`；空译文或缺失消息沿 fallback 链回退，最终使用游戏原文。

`dictionary.json` 保存命名字典；没有字典时使用 `{}`。消息的可选 `[values]` 将 placeholder
绑定到字典，只有实际求值为字符串时才查字典，缺项保留原值。
可将消息拆入 `messages/*.nmsg`，合并后 ID 仍须唯一。格式与验证细节见
[I18n 架构](../architecture/i18n.md)。

## 运行与切换

```ts
I18n.defaultLocale
I18n.locale
I18n.select("en")
```

开发 Host 校验 `languages/<locale>/`；构建时将其编码为 `<locale>.nlang`，发行 Host 使用同一套校验。
切换请求由 Runtime 提交，成功后更新 `I18n.locale` 并重绘正文与公共区域，不新增历史项。
重绘保留已提交状态与随机进度；语言选择界面由作者定义。

当前自动文本目录覆盖连续正文与显式 `print`。动态脚本输出和导航标签没有自动编译期文本身份，
不要假定所有可见字符串都会进入模板。源码结构变化后，应重新导出并校验翻译。
