# Narrava Loom 源码规范

> 状态：规范已采用
>
> 更新日期：2026-08-23

## 目标

源码优先表达领域所有权和执行顺序。重构必须保持行为、错误和事务边界不变，不为未来平台提前建立空抽象。

## 规划文档

- 文件开头统一为一级标题、`状态`、`更新日期`，再进入正文。
- 更新日期使用 `YYYY-MM-DD`，只在文档内容发生有效变化时更新。
- 状态描述当前完成度，不保存逐轮开发日志；历史由 Git 记录。
- 文档只描述当前有效契约，未发布阶段不保留旧接口兼容说明。

## Rust 组织

- `rustfmt.toml` 固定 Edition、Unix 换行、四空格缩进和 100 列宽；不以个人编辑器设置改变仓库格式。
- `src/lib.rs` 是 Core crate 入口；`src/main.rs` 只是 CLI Host。
- 模块按职责拆分。生产源码单文件接近 800 行时必须进行职责审查；承担两个以上事务、控制器
  或平台边界时先拆为 facade 与命名子模块。紧密算法可以保留完整，但要在模块注释中解释
  为什么不能按自然边界继续拆分。
- facade 只保留共享类型、依赖和稳定导出；实现放入按领域动作命名的子模块。跨子模块所需的
  内部入口使用 `pub(super)`，不得为了拆文件扩大公共 API。
- 平台 Binding 与 Host Renderer 不进入 Core 模块。
- 新增公开类型前先确认它属于 Core、Host API、Presentation、Binding 或 Host Renderer 中哪一层。
- 局部变量显式标注类型；迭代闭包参数和类型已经完全清楚的字段访问不重复标注。
- 可见性从私有开始：跨子模块使用 `pub(super)`，crate 内共享使用 `pub(crate)`，只有宿主需要的契约使用 `pub`。
- 错误使用结构化类型；不得用日志替代错误返回，也不得在失败路径留下部分状态。

## 命名与注释

- Rust 类型使用 `UpperCamelCase`，函数、变量和模块使用 `snake_case`。
- PassageName、MacroName 等游戏身份保持原始大小写；只有 Macro 语法关键字按各自规则规范化。
- 注释解释职责、所有权、事务原因或容易误解的边界，不逐行复述代码。
- 公共类型和公共方法使用简短 `///` 文档；模块入口使用 `//!` 说明职责。
- 后续能力只能在 `docs/architecture/` 中明确标注为“后续”，不在源码留下长期 TODO 或伪实现。

## 测试

- 所有 `#[test]` 只放在 `src/tests/` 及其子目录。
- `src/lib.rs` 只保留一个 `#[cfg(test)] mod tests;` 挂载入口；业务源码不声明自己的测试模块。
- 测试文件按被测领域命名，并使用 `crate::...` 导入真实实现。
- 单个测试文件承担多个子领域、接近 1000 行或明显难以浏览时，拆入 `src/tests/<领域>/`；仍由
  `src/tests/mod.rs` 统一挂载。大量独立用例不是保留三千行测试文件的理由。
- 测试名称描述可观察行为，不描述内部调用步骤。
- 测试只为访问内部实现而需要的项目使用最小 `pub(crate)`；不能为了测试把内部类型升级成公共 API。
- 行为变更先写会失败的测试；纯重构不得通过修改断言来获得通过。

## 每步验证

```text
cargo fmt --all
cargo check --all-targets
cargo clippy --all-targets -- -D warnings
cargo test
git diff --check
```

CLI 边界变更还需运行 `cargo run --quiet -- examples`。工作区包含用户未提交改动时，不自动暂存、提交或创建分支。
