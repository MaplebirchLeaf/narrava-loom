# Narrava I18n

> 状态：I18n 文本闭环已完成
>
> 更新日期：2026-08-23

## 边界

I18n 管理“显示哪段语言文本”，属于 Core 语义，不依赖 HTML、CSS、Godot 或其他 Renderer。

```text
HIR 连续可见文本与显式 print
→ I18nCatalog
→ I18nTemplate
→ translations.nmsg + dictionary.json
→ 校验、动态字典与显式语言回退链
→ 游戏默认语言原文
→ Surface Text
→ Host Renderer
```

翻译只能替换文本和调整受控 placeholder 的顺序，不能注入 Expression、Macro、Story 跳转或平台表现对象。

当前完成边界是 Compiler 能确定身份的 Passage Text 与显式 `print`。`link` 等 Macro 的 Interaction label 由 Macro 参数在运行时产生；在 Macro 参数拥有编译期表现语义之前，Core 不伪造其 I18n 身份。自定义 Macro 若产生可翻译表现内容，后续应通过明确的语义文本 API 登记，不能靠 Runtime 字符串扫描。

## `.nlang` 语言包

`.nlang` 是 ZIP 内容格式的安装与分发容器。正式翻译内容按职责拆为紧凑 NMSG 与动态字典 JSON，不再保留合并文件或并行的第二份真值。

```text
languages/zh-CN.nlang
├── manifest.json
├── translations.nmsg   稳定消息 ID、原文、译文与 placeholder 绑定
├── dictionary.json     全部命名字典
└── resources/          可选，本地化逻辑资源
```

一个 `.nlang` 只对应一个 locale，并以 `languages/<locale>.nlang` 安装；文件名与 `manifest.json` 声明的 locale 必须一致。`manifest.json` 的最小职责是声明语言、可选 fallback、语言包版本、目标游戏身份与兼容版本。Core 已提供 `GameIdentity` 与 `GameCompatibility` 作为 Config、Mod、语言包和 Save 的共享规则；manifest 必须复用它们，不能在 I18n 内建立另一套游戏识别规则。

当前最小 schema 为：

```json
{
  "locale": "zh-CN",
  "fallback": "zh",
  "version": "1.0.0",
  "game": {
    "id": "example.forest",
    "versions": ">=0.3.1, <0.4.0"
  }
}
```

`fallback` 可以省略；其余字段必填。未知字段、非法 locale、非法语言包版本和非法目标游戏约束都会被拒绝。安装时必须满足文件名 locale 与 manifest locale 一致，并且目标游戏 ID 与版本范围匹配。NMSG 不重复声明 locale。

`translations.nmsg` 使用 `:: id`、`[source]`、`[translation]` 与可选 `[values]` section。section 内不放装饰空行，两条消息之间恰好保留一个空行；这个空行不属于译文。`values` 每行使用 `placeholder = dictionary`。`dictionary.json` 的顶层键是字典名，第二层是运行时原值到目标文本的字符串映射。空字典是合法内容，两份文件均为必需文件。

NMSG 是语言包内唯一的消息真值。翻译工具可以把它二次解析为 CSV、PO、XLIFF 或按消息拆分的多文件工作区，再通过稳定 ID 合回 NMSG；这些工作格式不进入 `.nlang`，Runtime 也不直接读取它们。

清单当前不携带 `format_version`。Narrava 尚未发布，也不存在需要并行识别的旧语言包格式；真正出现不兼容变更时再定义清晰的迁移边界。

语言包不得携带或执行 scripts、Macro、Expression 与任意 Host 对象。当前文件白名单只有根目录的 `manifest.json`、`translations.nmsg`、`dictionary.json`，以及 `resources/**/*.nres`。开发阶段可使用同样的解包目录，发布时由 Binding 编码为 `.nlang` ZIP。

Binding 解压 ZIP 时必须先限制压缩包总大小、解压后总大小、单文件大小和条目数量，再把内存条目交给 `NlangPackageInput`。Core 随后拒绝绝对路径、反斜杠、盘符、控制字符、空段、`.`／`..`、重复路径和白名单之外的文件；Core 不自行拼接磁盘路径，因此不会把宿主文件系统变成语言包语义的一部分。

## 实现

- `I18nCatalog::from_hir()` 按 Passage 和 HIR 结构顺序收集连续可见 Text；
- `I18nTextId` 由区分大小写的 PassageName 与结构路径组成，不使用原文或行号作为身份；
- 每条默认语言记录保留 SourcePath、PassageName、原文与 Source Span；
- `silently` 中不会进入 Surface 的正文不进入翻译目录；
- 相邻 Text、反引号字面 `print` 和表达式 `print` 会合并为一条消息，允许译者调整语序；
- `$`、`_`、`@`、`setup`、普通全局名称及其静态成员链保留为可识别 placeholder，例如 `$hero.profile.name`；动态索引、调用和计算表达式使用结构内稳定的 `value_n`；
- 只有动态值而没有静态文字的 `print` 不建立翻译条目；
- `I18nCatalog::template()` 生成可序列化的 `I18nTemplate`：每条消息分为编译器生成的只读 `source` 与译者填写的 `text`，新消息的 `text` 为空；
- 空 `text` 和缺失消息都明确回退默认语言，并标记为 `Default` 来源，不会伪装成已翻译；
- `I18nCatalog::validate()` 会聚合报告语言标签形状、未知消息、被修改的 `source`、placeholder 语法、缺失／新增 placeholder 和未知动态字典；
- 模板使用 `{name}` 表示 placeholder，`{{` 与 `}}` 表示源码中的普通花括号。
- `I18nCatalog::resolve()` 只接受已验证译文，按文本 ID 填充 Runtime 值；目标消息缺失时返回默认文本并明确标记 `Default` 来源；
- placeholder 可选择动态字典，但 VM 只允许实际求值为 String 的结果查询字典；Number、Boolean、Null 与 Undefined 只按显示规则插入。字典缺少具体字符串时保留原 Runtime 文本；未知消息和缺失 Runtime 值不会静默输出；
- 校验与解析共享唯一模板语法实现，避免花括号和 placeholder 规则漂移。
- `MirStory` 直接拥有由同一份 HIR 生成的 `I18nCatalog`；可翻译 Text／Print 指令通过 `MirI18nTextPart` 携带消息 ID，表达式片段同时携带 placeholder 名；
- 独立 `lower_body()` 不知道 Passage 与 Source 身份，因此不会伪造 I18n ID；
- VM 会把同一消息 ID 的连续 MIR 片段作为一次执行：按源码顺序求值 placeholder，再生成一个 Surface Text；
- `MirExecutionFrame::step()` 使用默认语言，`step_with_runtime_language()` 统一接受单语言或 fallback 链；目标语言可重排 placeholder、应用动态字典，并在缺少消息时回退默认文本；
- `EngineMirBeginRequest` 和 Host 的 MIR 请求携带统一的 `I18nRuntimeLanguage`；Engine 把单语言或完整 fallback 链复制进 `EngineMirProgress`，因此异步 Macro 暂停、恢复和跨 Passage 导航不会丢失语言选择；
- 每次 `I18nCatalog::from_hir()` 都建立新的编译目录身份；校验后的模板绑定该身份，目录克隆保持有效，但源码重编译或模组生成新有效构建后必须重新校验；
- `I18nCatalog::resolve()` 对其他目录的模板返回 `DifferentCatalog`，VM 转换为稳定的 `DifferentI18nCatalog` 执行错误，不以 panic 处理 Host 输入；
- `I18nCatalog::export()` 已提供不接触文件系统的确定性合并：同语言且 placeholder 兼容的旧译文原样保留，新消息加入当前模板，旧字典一并保留；
- 已删除消息和同 ID 但 placeholder 不兼容的旧消息不会进入可运行模板，而是以 `Removed`／`Incompatible` 原因完整保存在失效报告；跨语言模板返回 `LanguageMismatch`；
- `to_nmsg()` 与 `apply_nmsg()` 提供确定性 NMSG 生成与合并；未知／重复 ID、被修改的 source、非法 section 或重复 values 会被拒绝；
- `GameIdentity` 已统一解析区分大小写的游戏 ID 与 SemVer；`GameCompatibility` 使用同一 ID 规则和版本范围，可由 `.nlang`、`.nmod` 与 Save 共同复用；
- `NlangManifest::from_json()` 已实现无冗余格式版本字段的严格 schema；`validate_install()` 校验文件 locale、manifest 与当前游戏，并只在全部通过后产生 `NlangValidatedManifest`；
- `NlangPackageInput` 接收 Binding 提供的无序内存条目，要求唯一 UTF-8 `manifest.json`、`translations.nmsg` 与 `dictionary.json`，并在包级检查完成后产生 `NlangValidatedPackage`；
- `NlangPackageOutput::build()` 生成按路径排序的三份正式文件；Binding 只需把清单编码为 ZIP 并保存为建议的 `<locale>.nlang`；
- Core 不选择安装目录、不打开文件，也不依赖 ZIP 库；
- `NlangValidatedPackage` 中的译文仍只是包级可信，进入 Runtime 前必须继续由当前有效构建的 `I18nCatalog::validate()` 绑定目录身份；
- `I18nLanguageChain` 把首选语言包及其 manifest 声明的 fallback 顺序绑定当前目录；重复 locale、缺失 fallback、顺序不一致和任一层无效译文都会拒绝整条候选链；
- `I18nLanguageChain::select()` 可从无序安装包按 manifest 自动建立 fallback；`I18nRuntimeLanguage::select()` 在选择默认语言时返回 `None`，选择目标语言时返回完整链；
- 解析时首选层的消息缺失或 `text` 为空才继续下一 fallback，所有目标语言都缺失时才回到游戏默认原文；
- `MirExecutionFrame::step_with_runtime_language()` 已让 VM 通过唯一入口使用单语言或完整 fallback 链；语言选择必须绑定当前 `MirStory` 的目录身份，跨 Story 重建会在执行前返回 `DifferentI18nCatalog`；
- MIR 与目录按确定性结构顺序配对，不把可重复的 Source Span 当作身份。`silently` 和静默 include 仍只执行逻辑，不产生文本。
- 所有公开 I18n 错误都可通过 `I18nDiagnostic` 转成 `i18n.*` 稳定编号的 Error Diagnostic；
- `config.toml` 的 `default_locale` 使用与 manifest、译文相同的语言标签形状校验。

Surface 仍只接收最终宿主无关 Text，不暴露翻译模板、字典或 Source Span。

## 完成边界

I18n 的目录、翻译工具、`.nlang`、字典、fallback、VM、Engine、Host 和 Diagnostic 文本链已经闭合。ZIP 压缩、安装目录和语言选择 UI 属于 Binding；Interaction label 的编译期身份属于后续 Macro／Surface 语义扩展。

后续 Mod patch 与有效构建继续由独立 `narrava-loom-modloader` crate 负责，现状见 [/docs/architecture/modloader.md](/docs/architecture/modloader.md)。

翻译文本只能重排目录声明的 placeholder，不能新增 Expression 或 Macro。
